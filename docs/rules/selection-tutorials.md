# Selection Tutorials

Система пошаговых подсказок страницы `/selection`. Почти каждая карточка оборудования имеет собственный сценарий обучения, запускаемый кнопкой «Подсказки» (?) в шапке карточки.

## Реализация

- Компонент поповера: `resources/js/components/TutorialPopover.jsx`.
- Сценарии и состояния шагов: `resources/js/selection.jsx`.
- Состояния сценариев в главном компоненте selection: `boilerTutorialStep` (+ `boilerTutorialNextStep`), `mixingTutorialStep`, `gvsBoilerTutorialStep`, `pumpTutorialStep`, `thermostatTutorialStep`, `zoneTutorialStep`, `otherEquipmentTutorialStep`, `temperatureSensorTutorialStep`, `leakTutorialStep`.
- Якоря поповеров — refs на элементы карточки: поля переключателей (`connectionRef`, `servoRef`, `sensorRef`, `pumpTypeRef`, ...), кнопку добавления (`addRef`), блок списка добавленного (`addedListRef`), счётчик первой строки (`counterRef`), блок настроек (`*SettingsRef`).

## Общее поведение

- Кнопка «Подсказки» переключает обучение: первый клик включает первый шаг сценария, повторный клик или крестик поповера выключают его (`step = null`). Активность подсвечивается статусом «Включены/Выключены».
- Поповер всегда размещается над якорным элементом и соединяется с ним SVG-линией с точками на концах.
- Поповер следует за якорем при ручной прокрутке. Если он выходит из видимой области или попадает под фиксированный header, маска временно становится сплошной без отверстия, а соединительная линия и `blockContent` скрываются. Они восстанавливаются, когда поповер снова целиком виден.
- `showMask` затемняет страницу, оставляя видимой зону якоря (и опционального `highlightRef`) с отступом 8px.
- `type="blockContent"` ставит прозрачный блокиратор над выделенной зоной: клик по нему вызывает анимацию привлечения внимания, а содержимое списка недоступно до нажатия «Далее».
- Шаги продвигаются двумя способами: навигационной кнопкой внутри поповера либо автоматически, когда пользователь выполняет реальное действие (переключает опцию, добавляет устройство). Кнопки поповера меняют только шаг обучения и никогда не изменяют конфигурацию подбора. Автопродвижение срабатывает только если соответствующий шаг сейчас активен.
- Финальный шаг закрывается кнопкой «Понятно» либо «Далее» без следующего шага. Повторный запуск сценария всегда начинается с его первого шага.
- Сценарии разных карточек независимы: активное обучение одной карточки не закрывает обучение другой; одновременно активен один шаг на карточку.
- Обучение не изменяет данные подбора напрямую: данные меняют только обычные обработчики переключателей и добавления устройств, а шаги лишь следуют за ними.

## Сценарий «Котлы» (`boilerTutorialStep`)

Самый сложный сценарий: `input → select → added-list → connection | add-more → search-more`.

1. `input` — поповер над строкой поиска: «Введите название котла или производителя в это поле». При включении любого шага этого сценария страница плавно скроллится наверх.
2. `select` — включается автоматически, как только у непустого запроса появились результаты поиска. Подсвечивает поле ввода вместе с выпадашкой результатов. Закрывается без перехода, если выпадашку закрыли кликом мимо или Escape.
3. Выбор котла из списка переводит сценарий в `added-list` и запоминает следующий шаг в `boilerTutorialNextStep`:
   - `smart` (BUS, `bus_type !== 127`) → далее `connection`;
   - `stupid` (RELAY, `bus_type === 127`) → далее `add-more`.
4. `added-list` — `blockContent` над списком добавленных котлов: «Выбранный котел добавлен…», кнопка «Далее» ведёт на сохранённый следующий шаг.
5. `connection` — поповер над переключателем BUS/RELAY последнего добавленного smart-котла: тип подключения меняют, только если котёл резервный и садится на реле. Переход на `add-more` происходит либо переключением тумблера, либо кнопкой «Оставить без изменений». Для stupid-котлов шаг пропускается.
6. `add-more` — поповер над кнопкой «+ Добавить котёл»: предложение добавить другие котлы. Клик по кнопке открывает выпадашку и переводит сценарий в `search-more`.
7. `search-more` — подсветка поля ввода и выпадашки: выбрать дополнительный котёл из списка или искать по другому запросу. Сценарий завершается закрытием поповера.

## Сценарий «Смесительные узлы» (`mixingTutorialStep`)

Цепочка: `connection → servo → sensor → add → added-list → add-more → configuration → configuration-add`.

1. `connection` — над полем «Тип подключения»: проводное или Wi-Fi. Wi-Fi допустим только для совместимого узла 220V с цифровым датчиком (выбор Wi-Fi обычным переключателем выставляет сервопривод 220V и цифровой датчик). Смена типа или кнопка «Далее без изменений» ведут на `servo`.
2. `servo` — над полем «Сервопривод»: 220V или 0-10V по маркировке привода. В режиме Wi-Fi доступен только 220V. Смена значения ведёт на `sensor`.
3. `sensor` — над полем «Датчик»; текст зависит от контекста:
   - Wi-Fi: цифровой датчик уже выбран автоматически;
   - привод 0-10V: нужен NTC, цифровой не используется;
   - иначе: объяснение различий цифрового (1-Wire) и NTC.
   Кнопка «Далее без изменений» ведёт на `add`; выбор типа выполняется только самим переключателем.
4. `add` — над большой кнопкой добавления; сводка выбранных опций («Выбрано: …»). Если этот вариант уже добавлен, якорем становится список добавленных, текст меняется на «уже добавлен», а кнопка «Показать счётчик» ведёт сразу на `add-more`.
5. `added-list` — `blockContent` над списком; открывается после фактического добавления узла, кнопка «Далее» ведёт на `add-more`.
6. `add-more` — над счётчиком строки добавленного варианта: счётчики «+/−» меняют количество одинаковых узлов, другой вариант добавляется сменой опций выше, модули контроллера подбираются автоматически. Кнопка «Далее» ведёт на `configuration`.
7. `configuration` — над блоком настроек: смените конфигурацию добавления, чтобы добавить другой вид смесительных узлов. Шаг ждёт фактического изменения настройки.
8. `configuration-add` — после изменения конфигурации подсвечивает настройки и кнопку добавления. Кнопка «Понятно» завершает сценарий.

## Сценарий «Бойлеры ГВС» (`gvsBoilerTutorialStep`)

Цепочка: `intro → added-list → count`.

1. `intro` — над кнопкой добавления; если бойлер уже добавлен, якорь переносится на счётчик строки, текст меняется на «уже добавлен», доступна кнопка «Показать счётчик» → `count`. Текст объясняет, что бойлер косвенного нагрева учитывается вместе с насосом бойлера и датчиком температуры.
2. `added-list` — `blockContent` после добавления, «Далее» ведёт на `count`.
3. `count` — над счётчиком строки: счётчики «+/−», для каждого бойлера автоматически учитываются насос и датчик температуры. Кнопка «Понятно» завершает сценарий.

## Сценарий «Насосы» (`pumpTutorialStep`)

Цепочка: `connection → type → add → added-list → count → configuration`.

1. `connection` — над полем «Тип подключения»: по проводу или Wi-Fi (Wi-Fi использует свободный модуль RL6W/RL6SW и требует насос 220V). Смена типа или кнопка «Далее без изменений» ведут на `type`.
2. `type` — над полем «Управление»: 220V (релейное) или 0-10V (аналоговое). В режиме Wi-Fi доступен только 220V. Смена значения или кнопка «Далее без изменений» ведут на `add`.
3. `add` — над кнопкой добавления со сводкой выбора; если вариант уже в списке — якорь переносится на список и кнопка «Показать счётчик» ведёт на `count`.
4. `added-list` — `blockContent` после добавления, «Далее» ведёт на `count`.
5. `count` — над счётчиком строки: Wi-Fi-насосы система распределяет по свободным каналам Wi-Fi модулей. Кнопка «Далее» ведёт на `configuration`.
6. `configuration` — над блоком настроек: смените конфигурацию добавления, чтобы добавить другой вид насоса. Кнопка «Понятно» завершает сценарий.

## Сценарий «Термостаты» (`thermostatTutorialStep`)

Цепочка: `connection → color → floor-sensor → add → added-list → count → configuration → configuration-changed`.

1. `connection` — над полем «Тип подключения»: по проводу или беспроводной (Wi-Fi). Смена типа или кнопка «Далее без изменений» ведут на `color`.
2. `color` — над выбором цвета корпуса. Фактический выбор цвета ведёт на `floor-sensor`.
3. `floor-sensor` — над опцией датчика пола. Изменение опции ведёт на `add`.
4. `add` — над кнопкой добавления: проверьте подключение, цвет и датчик пола. Если текущая конфигурация уже добавлена, якорь переносится на список, текст меняется на «уже добавлен», кнопка «Показать счётчик» ведёт на `count`.
5. `added-list` — `blockContent` после добавления: в списке все добавленные варианты термостатов. «Далее» ведёт на `count`.
6. `count` — над счётчиком первой строки списка: «+/−» изменяют количество одинаковых термостатов. «Далее» ведёт на `configuration`.
7. `configuration` — над блоком настроек: смените тип подключения, цвет или датчик пола, чтобы добавить другой вариант термостата. «Понятно» может завершить сценарий.
8. `configuration-changed` — после изменения настройки подсвечивает конфигурацию и кнопку добавления. Добавление новой конфигурации или кнопка «Понятно» завершают сценарий.

## Сценарий «Зоны» (`zoneTutorialStep`)

Общий компонент `ZoneCard` без режима `isOtherEquipment`. Цепочка: `connection → add → added-list → count`.

1. `connection` — над полем «Тип подключения»: проводной сервопривод зоны или Wi-Fi (размещается на свободном канале RL6W/RL6SW). Смена типа или кнопка «Далее без изменений» ведут на `add`.
2. `add` — над кнопкой добавления со сводкой; если вариант уже добавлен — якорь на список и «Показать счётчик» → `count`.
3. `added-list` — `blockContent` после добавления, «Далее» ведёт на `count`.
4. `count` — над счётчиком строки: Wi-Fi сервоприводы зон распределяются по свободным каналам Wi-Fi модулей автоматически. Кнопка «Далее» завершает сценарий (без шага `configuration`).

## Сценарий «Прочее оборудование» (`otherEquipmentTutorialStep`)

Тот же компонент `ZoneCard` с `isOtherEquipment`; тексты шагов адаптированы под оборудование (сирены, реле и т.п., одно устройство — один релейный порт). Цепочка: `connection → add → added-list → count → configuration`.

1. `connection` — проводное или Wi-Fi подключение (Wi-Fi размещается на свободном канале RL6W/RL6SW). Переход на `add`.
2. `add` — сводка выбора; при уже добавленном варианте — якорь на список и «Показать счётчик» → `count`.
3. `added-list` — `blockContent` после добавления, «Далее» ведёт на `count`.
4. `count` — над счётчиком строки: Wi-Fi устройства распределяются по свободным каналам Wi-Fi модулей. «Далее» ведёт на `configuration`.
5. `configuration` — над полем типа подключения: смените конфигурацию, чтобы добавить другой вид оборудования. Кнопка «Понятно» завершает сценарий.

## Сценарий «Датчики температуры» (`temperatureSensorTutorialStep`)

Цепочка: `connection → placement → kind → add → added-list → count`.

1. `connection` — над полем «Тип подключения»: проводной датчик или беспроводной (Wi-Fi). Смена типа или кнопка «Далее без изменений» ведут на `placement`.
2. `placement` — над полем «Расположение»: настенный датчик или датчик в колбе. Для беспроводного подключения доступен только настенный вариант. Переход зависит от типа подключения: проводной → `kind`, беспроводной → сразу `add` (поле типа для беспроводных скрыто).
3. `kind` — над полем «Тип датчика»: тип указан в маркировке или паспорте. Смена значения ведёт на `add`.
4. `add` — над кнопкой добавления: проверьте конфигурацию и добавьте датчик. Фактическое добавление ведёт на `added-list`. Если вариант уже добавлен и кнопка скрыта, якорь переносится на список, а «Показать счётчик» ведёт на `count`.
5. `added-list` — `blockContent` над списком всех добавленных датчиков, «Далее» ведёт на `count`.
6. `count` — над счётчиком строки: «+/−» изменяют количество одинаковых датчиков. Кнопка «Понятно» завершает сценарий.

## Сценарий «Контроль протечки» (`leakTutorialStep`)

Цепочка: `add-zone → added-list → zone-count → valve-count`.

1. `add-zone` — над кнопкой «Добавить группу датчиков протечки»: датчики одной группы образуют шлейф и занимают один дискретный вход; для независимой зоны добавляется отдельная группа. Добавление группы ведёт на `added-list`.
2. `added-list` — `blockContent` над списком групп: в каждой группе указывается число датчиков одного шлейфа. «Далее» ведёт на `zone-count`.
3. `zone-count` — над счётчиком датчиков первой группы: «+/−» изменяют число датчиков в шлейфе. «Далее» ведёт на `valve-count`.
4. `valve-count` — над счётчиком запорных клапанов: клапаны задаются отдельно от зон, каждый занимает два соседних релейных порта. Кнопка «Понятно» завершает сценарий.

## Карточки без сценариев

Поповеры обучения есть не везде. Без сценариев остались: уличный радиодатчик температуры (тумблер вместо счётчика), датчик давления, дискретные входы и выбор контроллера.

## Инварианты

- Поповер никогда не меняет сторону размещения относительно экрана: он всегда над якорем.
- Автопродвижение шага выполняется только из активного шага; ручные клики мимо сценария не ломают цепочку.
- Если вариант оборудования уже добавлен, шаг `add`/`intro` переключает якорь с кнопки на список и предлагает перейти к счётчику количества.
- В общих карточках шаг `count` привязан к счётчику первой строки списка; один ref не назначается одновременно нескольким строкам.
